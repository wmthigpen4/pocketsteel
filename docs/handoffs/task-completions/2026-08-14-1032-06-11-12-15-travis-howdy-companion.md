# Deterministic Travis Howdy companion implementation

## Task summary

Implemented the isolated, deterministic Travis Toy Tutorials Howdy companion
as a standalone static Pages product surface.

The implementation includes:

- a Travis Toy Tutorials full-page practice workspace at `/howdy`;
- a compact Teachable-style demonstration at `/howdy/embed-demo`;
- a browser-print view and generated notation-plus-ten-string-E9 PDF at
  `/howdy/print`;
- a canonical `lesson_companion_v1` artifact with stable phrase, chord, event,
  fretboard, tab, notation, and print references;
- deterministic playback clock, seeking, speed, looping, current/next move,
  fretboard, tab highlighting, mode/layer selection, and feedback context;
- an allowlisted Direct Upload packager, release manifest, hash verifier, and
  gated publisher for `steel-guitar-rag-travis-preview`;
- CSP/security/cache headers and a branded static 404;
- a Cloudflare Pages and Access deployment runbook.

The tracked artifact is intentionally a draft layout proof. It uses only the
lesson mechanics observed during product discovery, visibly withholds all
unreviewed chord names, marks every musical event unverified, omits licensed
audio and brand files, and carries a draft banner in the UI and PDF. Release
mode refuses to package it.

No Steel Guitar RAG application navigation, RAG endpoint, model client,
retrieval URL, Mac mini service, corpus content, transcript/VTT, Teachable
OAuth, credential, analytics, or private partner asset is present in the
bundle.

## Deterministic and musical guardrails

- Artifact runtime is `published_deterministic` with
  `modelCallsAllowed: false`.
- Browser code performs one same-origin fetch for canonical JSON and accepts
  same-origin audio only.
- There is no XMLHttpRequest, WebSocket, EventSource, beacon, Worker, answer,
  search, Ollama, Chroma, or provider client.
- Chord Foundation displays a review gate instead of invented chord symbols.
- Alternate positions remain comparison-only and cannot mutate the route.
- The packager validates unique event IDs, continuous authored timing, phrase
  membership, chord references, ten-string/fret ranges, phrase boundaries,
  authored duration, and 50 ms chord containment.
- Artifact hashing excludes only build SHA and generated asset URLs. The
  approved-content hash additionally covers CSS, JavaScript, audio, brand
  photo, and webfont hashes and becomes the asset-directory name.
- Release mode requires exact two-person Access identities, all human
  approvals, event/chord verification, approved copedent/print layout,
  approval references, exact private-asset hashes, all three Access app IDs,
  anonymous-denial checks, and an unchanged main app policy.
- Tester email addresses are never emitted to the bundle or manifest.
- The publisher rejects drafts and requires a separate
  `--deploy-reviewed-bundle` acknowledgement after verification.

### Cloudflare Pages local preflight

Wrangler `4.123.0` was inspected. The current `wrangler pages deploy` command
has no dry-run option, so `wrangler pages dev` was used as the supported
non-uploading Pages preflight.

Verified through the Pages runtime:

- `/` - 302 to `/howdy`;
- `/howdy/`, `/howdy/embed-demo/`, `/howdy/print/` - 200;
- `/api/answer`, `/api/search`, `/ui/example`, `/chat`, `/melody`, `/lessons`,
  encoded traversal, and an unknown path - branded 404;
- HTML and companion JSON - `Cache-Control: no-store`;
- content-hashed JavaScript -
  `Cache-Control: private, max-age=31536000, immutable`;
- same-origin CSP, no-referrer, nosniff, frame denial, object/form denial,
  permissions policy, CORP, and noindex headers - present.

Pages adds a trailing-slash 308 for slashless directory routes before serving
the corresponding 200 response. The intended no-slash URL remains usable.
